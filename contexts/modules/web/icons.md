# Entity icons & the icon picker (web)

> Every envelope / account / category / event carries a `color` and an `icon`. The icon is a plain string: either a key from the curated Lucide registry or a raw emoji. One resolver (`getIcon`) renders both; one picker (`IconPicker`) offers both behind a single search.

## Files

- `apps/web/src/lib/entityIcons.ts` — curated Lucide registry (~610 keys in 14 presentation categories; `ENTITY_ICONS` has a null prototype so a persisted `"constructor"` can't resolve to `Object`), `getIcon()`, `canonicalIconName()`, `LEGACY_ICON_ALIASES`. Edited by hand (the `CATEGORIES` table).
- `apps/web/src/lib/emoji.ts` — emoji half: `isEmojiIcon`, `emojiKey`, skin-tone helpers, dataset types + `parseEmojiDataset`, canvas-based platform-support probe. No DOM access at module scope (the generator imports it under Node).
- `apps/web/src/lib/icons/load.ts` — lazy loaders: `loadEmojiDataset` / `loadLucideTags` `fetch()` the generated JSON as static assets (`?url` imports), cached per session, retryable.
- `apps/web/src/lib/iconSearch.ts` — tokenizer, the budgeting `SYNONYMS` table, `GENERIC_TERMS`, index builders, ranked search with stems, typo tolerance and the partial-match fallback.
- `apps/web/src/lib/autofocus.ts` — `focusOnOpen(selector)` for Radix `onOpenAutoFocus` (skips touch devices).
- `apps/web/src/lib/icons/emoji.generated.json` — 1.9k emoji tuples `[emoji, label, group, version, tags, skin]` + per-version probes. **Generated.**
- `apps/web/src/lib/icons/lucide-tags.generated.json` — search tags for every registry key (from lucide-static). **Generated.**
- `apps/web/scripts/generate-icon-data.mts` — the generator (`pnpm generate-icons` from `apps/web/`; fetches pinned `emojibase-data` + `lucide-static` from jsDelivr).
- `apps/web/src/components/shared/EmojiGlyph.tsx` — renders an emoji in a 24×24 SVG viewBox so it sizes like a Lucide icon.
- `apps/web/src/components/shared/IconPicker.tsx` — `IconPicker` (inline panel), `IconPickerButton` (popover trigger). `EntityStyleFields.tsx` wraps the inline panel in its own popover (preview-row variant).

## Storage format

- Server validates `icon` as `z.string().min(1).max(48)`; the column is `varchar(48)`. Longest RGI emoji sequence is 10 code points / 15 UTF-16 units, so emoji fit with no migration.
- No server-side whitelist. Unknown Lucide keys render the `Baseline` fallback; anything emoji-shaped (`isEmojiIcon`) renders as text. Consequence worth knowing: a member on a 2025 phone can pick an Emoji 16/17 glyph that a teammate's older OS shows as tofu — the probe limits what you can _pick_, not what you _see_.
- Skin-toned emoji are stored as picked (`"👍🏽"`). `emojiKey()` strips tone + presentation selectors for identity (active-cell highlight, recents dedupe).

## Rendering

- `getIcon(name)` returns an `EntityIconComponent` accepting `className | size | color | strokeWidth | aria-*`. Lucide icons pass straight through; emoji get a cached component bound to `EmojiGlyph`. `style` is deliberately not in the contract — two `@types/react`/csstype copies in the workspace make `CSSProperties` non-comparable across Lucide's props and ours.
- `EmojiGlyph` uses `<text>` inside `viewBox 0 0 24 24` (font-size 19 — colour-emoji fonts are ~1.2em tall and the outer `<svg>` clips — `dominant-baseline: central`); a size-\* class or the `size` prop scales it exactly like Lucide. Decorative (`aria-hidden`) unless given `aria-label`/`role`.

## Picker behaviour

- **Header**: tinted chip + name of the hovered/focused cell (a live preview; falls back to the current value — cells also carry a `title` tooltip), plus **Revert** when the host passed `defaultValue`/`defaultIcon` and the value differs. `defaultValue` is _the icon the form opened with_: the saved icon when editing (Categories inspector `node.icon`, Envelopes `envelope.icon`, Events `event.icon`, Account detail `currentIcon`), the type default when creating (Categories `folder`, Envelopes `mail`, Accounts `DEFAULT_ICON_BY_TYPE[type]`, Events `calendar-days`). Revert calls `onChange` directly — it is an undo, not a pick, so it doesn't enter Recent — and `onChange` is the host's handler, so Revert closes the popover like a pick. "Unknown icon" is shown for a value that is neither a registry key nor an emoji (renders the `Baseline` fallback). Decision: there is deliberately no "no icon" option — every entity has an icon; the column is NOT NULL with a per-table default and the server requires `min(1)`.
- Two tabs (Icons / Emoji); the initial tab follows the current value. Tabs and the category strip hide while searching; results show "Icons · n" and "Emoji · n" sections. Both popover hosts **close on select** (the panel is 512px tall and covers the preview); the ColorPicker deliberately stays open for comparing swatches. Host rule: `IconPickerButton` (glyph + chevron — an icon is its own label, unlike a hex) for compact Style rows beside a name field; `EntityStyleFields` where the form has room for the live preview row (Events, Account detail).
- **Search**: `tokenize()` lowercases, strips diacritics, splits on non-alphanumerics; possessive `'s` is stripped, and in multi-word queries one-character tokens and filler words (and, of, out, my…) are dropped. Tiers per term: primary-synonym exact 3.5 / label exact 3 / synonym exact 2.5 / label prefix 2 / primary-synonym prefix 1.75 / synonym prefix or tag exact 1.5 / tag prefix 1 / label substring (≥4 chars) 0.75 / category or Unicode-group name 0.5 (prefix 0.35) — tags get no substring rule, and a one- or two-letter term only counts as a weak, still tier-ordered hint (1.4 / 1.3 / 1.2) when it merely prefixes a token ("AC bill" must not become `activity`). Whole-label match +2, and an exact _primary synonym_ earns the same +2 (🏏 "cricket game" beats 🦗 "cricket"). A term counts as _genuinely_ matched from 1.5 up (drives the sort) and as _exactly_ answered from 2.5 up (label/synonym exact — a prefix is not enough, or a coincidence like "car"→"card" would gate "car loan" and hide every car and loan icon; `credit-card` may still rank first there, the real answers follow). When some item exactly answers every term ("credit card", "house rent") full matches lead and up to 24 of the strongest partials trail; otherwise partial matches stand in ("Emergency fund", "School fees", "car wash" → car before a "care"-tagged brush), ordered by genuinely-matched terms, then score. Query terms also try naive singulars at a 0.6 discount (`groceries`→`grocery`, `cookies`→`cookie`, `taxes`→`tax`) — a stem only wins when it is the whole label (`tickets` → 🎫 ticket before 🎟️ admission tickets; `news` keeps 📰 above "new moon"). Terms of ≥5 letters that match nothing at all also try one-edit typos against labels and synonyms ("grocerries", "sallary", "resturant") at a weak score tiered by where the near-miss landed (primary synonym > label > other synonym), so the line's primary icon wins its own typo. Adjacent single letters are rejoined ("A/C" → "ac"); a query of nothing but filler words returns nothing. Capped at 480 per kind ("480+"). A pasted emoji matches itself and keeps its tone (Enter and click store the same canonical glyph); an emoji the device can't render isn't offered even when pasted.
- **Synonyms** (`SYNONYMS` in `iconSearch.ts`): budgeting vocabulary CLDR/Lucide never use — salary, rent, groceries, utilities, WASA/DESCO/Titas, EMI, DPS, bKash, rickshaw, CNG (the three-wheeler, not the fuel), Eid, Qurbani, Puja, Boishakh, Hajj, "fund", "bill"… The first target of each kind per line is that term's _primary_ icon and beats exact label hits (`car` → 🚗 "automobile" before "railway car"). A line's primary is fixed for all its terms, so split a line when one term wants a different icon (`barber` → 💈, `takeout` → 🥡). Keep generic icons (`sparkles`, `landmark`) off topical lines — a target on many lines becomes a false "answers every term" magnet for two-word names. **Generic money-words** (`GENERIC_TERMS`: fund, bill, fee, payment, cost, budget, subscription, membership…) are down-weighted ×0.4 in multi-term queries that also have a topical term, so "School fees" → school and "Gym membership" → dumbbell. Unknown targets are ignored. Re-test with two-word names and possessives ("Cox's Bazar trip"), not single words.
- **Keyboard**: the popover opens with focus in the search box (`focusOnOpen`, not Radix's first-tabbable — the header's Revert button would win). Exactly one cell in the body carries `tabIndex=0` (the current value's cell in the first section that shows it — Recent and its category both can — else the first cell), so Tab passes through the grid in one stop; arrows move between cells _and across groups_, Home/End within a group; ArrowDown from the search box enters the grid; Enter picks the first result and is always `preventDefault`ed so it never submits the host form. The category strip and the tone dots are each one Tab stop with Left/Right arrows. Escape closes the popover (Radix); Enter in the search box ignores an IME's commit-Enter (`isComposing`). Cells are `role="radio"` inside per-grid `radiogroup`s — arrows move focus without selecting, a documented deviation from the native radio model.
- **Data**: the emoji dataset (~120 KB) and Lucide tags (~50 KB) are fetched when the picker mounts and module-cached; search works by name until tags arrive. `detectEmojiSupport()` draws one probe per Emoji spec version (17 → 11) in red and blue on a canvas: colour glyphs ignore `fillStyle` (compared with a 60/255 tolerance and an alpha floor so Brave/RFP canvas noise doesn't flip it), tofu/monochrome fallbacks don't, and unsupported ZWJ sequences measure ≥1.6× a single glyph. Emoji newer than the first passing probe are hidden; country and subdivision flags are hidden when `🇧🇩` fails (Windows). If even 😀 fails, the canvas is treated as untrustworthy (privacy browsers) and Emoji ≤15.1 are assumed.
- **Skin tones**: 24px-hit-area dots in the sticky header of "People & Body" (the only group with tone-capable emoji) and in search results when any hit supports tones — never repeated in Recent, which just renders in the chosen tone. `applySkinTone()` only handles single-person sequences — the generator verifies each against emojibase's own variants and flags multi-person ones `skin: 0` (offered neutral). Tone persists in `localStorage["orbit:icon-picker:skin-tone"]`; a toned current value wins on open.
- **Recents**: last 24 picks in `localStorage["orbit:icon-picker:recent"]`, shown per tab (8 — one row on desktop), emoji filtered to what the device supports. The list is snapshotted per mount so a pick never reorders the row under the cursor.
- **Mobile / short viewports**: search input is 16px on coarse pointers (13px with a fine pointer) so iOS doesn't zoom on focus; auto-focus is suppressed on touch devices (`lib/autofocus.ts`) so the keyboard doesn't cover the panel on open; cells are ≥40px (the grid's `minmax(40px, 1fr)` is the only floor); the strip fades its right edge while it can scroll further. The panel sits in a size-container shell (`.op-icon-shell`; a container query can't style its own container): under 340px of popover room it hides the strip and tightens the header, under 260px it drops the header too, so the grid keeps space instead of being clipped. Landscape phones with a mid-screen trigger still get a very short grid — a bottom sheet would be the durable answer if that matters. `EntityStyleFields` wraps its triggers under the preview at ≤~400px.
- **Performance**: emoji group `<section>`s use `content-visibility: auto` with a `contain-intrinsic-size` hint computed from the measured column count (ResizeObserver on the body); grids are `memo`ised and only the group containing the selection receives `active`/`roving`, so a pick re-renders two groups, not 2.5k cells. Group headers are `position: sticky`; `scrollToSection` re-aims once on the next frame because skipped sections above settle their height late.

## Conventions & gotchas

- **Registry keys are persisted — append only.** Categories are presentation and can be reshuffled, but each key must appear in exactly one; `Object.assign` would silently merge duplicates, which is why the generator asserts `categories + legacy aliases === registry size`.
- **Legacy aliases:** `home`≡`house`, `train`≡`tram` are the same Lucide glyph (upstream renames). They stay in `ENTITY_ICONS` but not in any category; the picker highlights the canonical key via `canonicalIconName()`.
- **Aliases are easy to add by accident.** Lucide exports many names for one component (`Utensils`/`ForkKnife`, `Stars`/`Sparkles`, `FileSignature`/`FilePenLine`). Before adding an icon, check `L.A === L.B`; the picker would show two identical cells.
- Lucide renamed many icons after our keys were chosen; `LUCIDE_TAG_ALIASES` in the generator maps old keys to current `lucide-static` tag keys. The generator warns about keys with no tags (`podcast`, `history` today — they have none upstream and remain searchable by name).
- **Bundle cost (accepted):** the registry is imported eagerly by `EntityAvatar` and lands in the shared `entityStyle` chunk, which grew from ~95 KB to ~285 KB raw (~65 KB gzip) with the larger catalog. Cut on this branch to keep it in check: the 14 foreign-currency icons that were new here, amphora, the 12 zodiac signs (emoji has them all) — none persisted. `euro`/`pound-sterling`/`japanese-yen` predate the branch (persisted keys) and `indian-rupee` stays as the regional neighbour; Lucide has no ৳. The emoji dataset and search tags never enter a JS chunk. If this ever needs trimming, cut the catalog — don't lazy-load `getIcon`, every list row depends on it.
- `IconPickerButton` and `ColorPickerButton` each inject the shared `PICKER_TRIGGER_STYLES` (exported from `ColorPicker.tsx`) so either renders correctly on its own.
- `content-visibility` needs Chrome 85+/Safari 18+/Firefox 125+; older browsers just render everything (slower, still correct).
- The picker is `portal={false}` inside dialogs (focus trap / scroll lock). shadcn's `DialogContent` is transformed (`translate -50%`), which makes it the containing block for the `position: fixed` popover — **never leave `overflow` on it**; scroll an inner wrapper instead (`orbit-shell-host` and `CreateOrEditEventDialog` both do). The panel height reads `--radix-popover-content-available-height`, so don't wrap it in a container that hides that variable.
- Pass a stable `onChange` (a `useState` setter or `useCallback`) — the memoised grids re-render on every new function identity.
- Search is ASCII-token based: labels, tags and synonyms are English, so a Bangla query returns nothing — the empty state says so ("Search works in English — try “rent” or “groceries”.") rather than claiming nothing matches. Adding transliterated terms to `SYNONYMS` is the intended path.
- `apps/web/scripts/generate-icon-data.mts` runs under `tsx` and is not type-checked or linted by the app configs (no `@types/node` in the web app); its invariants are runtime assertions.
