`src/pages/space/analytics/views/TrendsView.tsx` is the largest analytics view (~2050 lines): period stepper bar + hand-rolled SVG `CumulativeRaceChart` and `YoYBars` (no Recharts), `EndpointStat` strip, `VelocityRow` list, movers grid.

**Why:** repeatedly reviewed; the same four structural traps keep recurring here and in any other hand-rolled-SVG + HTML-overlay chart.

**How to apply:**
- **HTML-overlay-on-SVG paint order.** These charts render `<svg>` then a series of absolutely-positioned `<span>` overlays (Y ticks, month labels, "Today", tooltip) in the same stacking context at `z-auto`. Anything appended AFTER an interactive overlay paints above it and steals clicks. Any new overlay span must carry `pointer-events-none` (the tooltip already does; the axis/month-label spans do not).
- **Column hit-width math.** `YoYBars` is `w=600 p=28`, 12 columns → `cw = 45.33` SVG units = 7.556% of container. Container = viewport − 32 (`.sl-main` px at <768) − 2 (Card border) − 48 (`CardContent p-6`). At 375px that is 293px → 22px per column; at 1024px the `lg:grid-cols-[1.4fr_1fr]` left column gives ~38px. Never assume a per-column overlay is a usable touch target.
- **`disabled` on chart-overlay buttons** breaks the parent container's `onMouseMove` tooltip (disabled form controls don't dispatch mouse events) and kills `title`. shadcn `<Button>` additionally hard-sets `disabled:pointer-events-none` in its base cva string, so `title` on any disabled shadcn Button never shows. Prefer `aria-disabled` + a guarded handler, or don't render the element.
- **`truncate` inside `inline-flex` needs `min-w-0` on the text span**, otherwise `white-space:nowrap` makes min-content = full text width and the label overflows its grid cell instead of ellipsizing. `EndpointStat` (label span) has this bug; `KpiStrip`/movers rows get it right via `min-w-0 flex-1`.
- **Group `opacity` as a "refreshing" signal fails AA.** Measured on this page's shadcn tokens (`--muted-foreground` hsl(180 10% 64%) on `--card` hsl(180 10% 9%) over `--background` hsl(180 10% 5%)): 7.50:1 at full opacity, **3.44:1 at `opacity-60`**, 5.21:1 at `opacity-80`. Use `opacity-80` max, and put `transition-opacity` unconditionally in the class list (conditional transition = fades in, snaps out).
- `refetchOnWindowFocus: false` + `staleTime: 30s` (App.tsx), so `isFetching && !isLoading` is a safe "replacement in flight" signal here; `isPlaceholderData` is the more precise one when `placeholderData: prev => prev` is used.
- Amber (`--warning`) is overloaded on this screen: `AnalyticsFilterBar` active chips use `border-warning/40 bg-warning/5`, and the period bar uses `border-warning/30 bg-warning/[0.05]` for "viewing history" — same tint, 16px apart, two meanings. `bg-warning/5` over `--background` is ~1.06:1 (invisible); the border + amber text carry the signal.
- `AnalyticsDetailLayout` root is `grid gap-5 sm:gap-6`, so a child's `-mt-1` yields a 16px visual gap. Stacking two `-mt-1` children (period bar + `AnalyticsFilterBar`) is NOT doubled — both gaps come out 16px. Verified.

**Round-2 additions (period stepper bar, `TrendsPeriodBar`):**
- **`aria-disabled` buttons keep `cursor:pointer` AND `hover:bg-accent`.** `src/index.css` @layer base has `button:not(:disabled) { cursor: pointer }` (specificity 0,1,1) *and* `[aria-disabled="true"] { cursor: not-allowed }` (0,1,0) — the first wins, so the not-allowed rule is dead for any button using `aria-disabled` without `disabled`. And `buttonVariants`' `hover:bg-accent` only guards on `disabled:`, so an aria-disabled ghost button still lights up on hover. Every `aria-disabled` control needs explicit `cursor-not-allowed hover:bg-transparent` (utilities layer beats base layer regardless of specificity).
- **`opacity-40` vs the app's `disabled:opacity-50`.** Measured `--foreground` on `--card`: 16.4:1 at full, **3.60:1 at `opacity-40`**, 4.92:1 at `opacity-50`. Both clear 1.4.11's 3:1 and both are exempt anyway (inactive control), but `opacity-50` matches `buttonVariants`' own `disabled:opacity-50` — prefer it for consistency.
- **`KpiStrip` skeleton is 4px shorter than its value.** `KpiStrip.tsx` renders `Skeleton h-7` (28px) against `KpiValue`'s `text-xl sm:text-2xl` (28px → **32px** at ≥640px). Toggling `isLoading` per interaction therefore jumps the page 4px/row (8–12px total) at every breakpoint ≥sm. Any `isLoading` driven by a *step* rather than a cold load needs `h-7 sm:h-8`.
- **Inter width budget for label columns** (px per em, 14.5px semibold ≈ ×1.04 of regular): `"Week of Sep 29, 2025"` ≈ **154px**, `" · Complete"` at 11px ≈ 62px incl. `ml-1.5` → a fixed `sm:w-[190px]` (178px content box) truncates permanently. `"September 2025 · Complete"` ≈ 180px — also over. Budget ≥232px for that headline.
- `EndpointStat` mobile track is **134px** (2-col grid, `gap-x-6`, 293px card interior) minus swatch+gap = **114px of text**. `"Typical month · avg of 11 earlier months"` at 10.5px ≈ 195px — still 1.7× over after shortening; and its `title` is unreachable on touch. The card description already states the sample count, so the label should just be `Typical ${noun}`.

**Round-3 additions — the "page shifts on every step" family.** The user's standing complaint on this page is that stepping/clicking must not move content. Four independent causes, all worth checking on any period-stepped view:
- **`scrollIntoView` scrolls the PAGE, not just the overflow container.** `el.scrollIntoView({inline:"center", block:"nearest"})` walks *every* scrollable ancestor including the document — if the horizontal chip row is below the fold, a step yanks the whole page down to it. For "centre the active chip in its own scroller", set `row.scrollLeft = el.offsetLeft - row.clientWidth/2 + el.offsetWidth/2` instead. (`display:none` elements have no box, so the same call silently no-ops at ≥sm — the bug is mobile-only and invisible on desktop.)
- **Copy length is layout.** Any `text-xs`/`text-[11px]` sub-line whose string differs between live/closed (or present/absent-comparison) flips line count at *some* width and moves everything below it. Measured budgets: chart `CardHeader` sub at 1024px viewport = 678px ⇒ ~115 chars/line, so live (153 chars) = 2 lines vs closed (109) = 1 line — a 16px jump on the exact interaction complained about. `KpiStrip` sub at lg 1024px = 142px ⇒ ~26 chars/line, so `All 31 days of September 2025` (29) wraps while `Day 12 of 31` doesn't. Fix pattern: fixed-line boxes (`truncate` per line, or `min-h-8` = 2× text-xs' 16px line box), never "shorten the string and hope".
- **Optional lines in the period bar.** `rangeLabel` is suppressed at year granularity; a YoY bar click from a year view switches to Month, which *adds* that line and shifts the page. Anything conditionally rendered above the fold on a nav path must reserve its height.
- **`--fg-3` / `--bg` / `--fg-4` are scoped to `.orbit-design`** (`src/styles/orbit-design.css`), not `:root` (`index.css` has only the shadcn HSL tokens). Analytics/Space/Overview roots all carry the class so they resolve, but an SVG `fill="var(--fg-3)"` in a component reused outside that scope falls back to `fill`'s initial **black**. Measured: `--fg-3` at `opacity 0.1` over `bg-card` lifts rgb(21,25,25)→(32,36,36) — a visible-but-quiet selection band; `0.06` (hover) → (28,32,32).

**Also verified round 3:**
- `buttonVariants({variant, size, className})` puts `className` **last inside the cva string**, and `cn` = `twMerge(clsx(...))`, so a caller's `hover:bg-transparent` / `cursor-not-allowed` genuinely defeats the variant's `hover:bg-accent` and `index.css`'s `button:not(:disabled){cursor:pointer}`. The `aria-disabled` recipe works — no Tailwind source-order gamble.
- **`divide-x` + `divide-y-0` on a wrapping grid has no row divider.** `KpiStrip`'s `sm:divide-x sm:divide-y-0` on a 2-column grid draws one full-height vertical line and *nothing* between rows, plus a dangling `border-left` on the cell that starts row 2. All 8 analytics views pass 4 items ⇒ 2×2 at 640–1023px. Use `gap-px` + `bg-border/60` on the container and `bg-card` on cells for column-count-agnostic cell borders.
- `TrendsPeriodBar` needs **653.6px** for one row (left group 304 + gap 12 + right group 313.6 + px-3 24), so `sm:flex-wrap` wraps it from 768px to ~950px viewport. `sm:ml-auto` on the right group right-aligns row 2 there (zig-zag); container `sm:justify-between` gives the same unwrapped result and left-aligns when wrapped.
- YoY column geometry: `cw=45.33`, `bw=(cw-6)/2=19.67`, bars laid out at `+3` ⇒ gaps 3 left / 2 inter / 1 right, so a column-aligned selection band has ~3× more clearance on the left than the right. `+2` centres the pair and makes the pair centre equal `cw/2` (where the month label sits).

**Round-4 additions — `MoversList` (the redesigned "Biggest movers" table).** Verified with a real headless-Chromium harness (see [[tooling-measurement-harness]]), not estimated.

- **Tailwind v4 emits `flex-basis` AFTER the `flex` shorthand.** Verified from generated CSS: `.flex-1{flex:1}` … `.basis-48{flex-basis:…}`. So `sm:flex-none sm:basis-48` ⇒ basis **wins** (192px fixed column, as intended), and `sm:flex-1 sm:basis-auto` ⇒ `basis:auto` wins (grow 1 / shrink 1 / basis auto). This is the **opposite of Tailwind v3**, where `flex` came after `flexBasis`. Never assume; the pair is order-dependent and the project is on v4.2.2.
- **The header/row column-mirroring trick works exactly.** A `hidden sm:flex` header with 6 items (5 gaps) mirrors a `flex-wrap` row with 4 items (3 outer gaps) whose 3 value spans sit in a nested `gap-x-3` div (2 inner gaps): 5×12 == 3×12 + 2×12. Measured `catX/nameX`, `barX/barX`, and all three right edges identical at 640–1440, and the header's `absolute left-1/2` `0` lands on the track's `absolute left-1/2` axis with **delta 0.0** at every width. Keep that gap-count identity in mind before adding or removing a header cell.
- **`min-w-0` does NOT zero a flex item's min-content *contribution*.** `<span class="relative min-w-0 flex-1">` containing `<span class="flex justify-between">−100% less / +100% more</span>` still contributed **65.58px** (the sum of the two labels' min-contents) to the non-wrapping header's min-content width, which inflated the whole card. `min-width:0` only lowers the flex *base/min* clamp; to stop content forcing an ancestor wider you need `overflow-hidden` (or `whitespace-nowrap` + `overflow-hidden`) on the item.
- **Fixed-width value columns are the trap on this page.** `w-[8.5rem] + w-[5.5rem] + w-[4rem]` + 2 gaps = **312px** of `shrink-0`, and with the 28px avatar + 192px label + 3 gaps the row needs **568px**. Card interior is 422px at 768px and 293px at 375px, so the card inflated its own grid track to 682px and the page scrolled **180px at 768px** (and 3px at 375 / 18px at 360). Measured natural content widths (Geist, tabular-nums): `999,999 → 999,999` = **106px**, `+999,999` with the `size-3` arrow = **72px**, `×999,999` = **56px** — i.e. 8.5/5.5/4rem carried ~48px of pure slack. Trimming to **6.75 / 4.75 / 3.5rem** and moving the tabular breakpoint from `sm:` to `lg:` removes all overflow at 360–1440 and *widens* the bar (110→158px at 1024) — verified in the harness.
- **`text-[9.5px] uppercase tracking-[0.08em]` label budget:** `−100% less` = 61.7px, `+100% more` = 66.59px, `−100%` = 32.61px, `Category` = 54.16px, `Jun → Jul` = 58.25px, but `September → August` = **119.84px** and a cross-year `December 2024 → January 2025` ≈ 186px. Any header cell built from `formatPeriodShort` output needs `truncate` — that helper returns `"MMMM"`, `"MMMM yyyy"`, `"Q3 2024"`, `"2024"`, or `"Jul 27–Aug 2"`, so its width varies ~3×. 9.5px itself is in-house (also `EnvelopesView` badges, `HeatmapView`) and contrast is fine (muted-foreground 7.5:1, `foreground/60` 6.55:1 on `--card`).
- **A `%`-based minimum bar segment is meaningless when the bar column is `flex-1`.** `width: max(1.5%, halfFill)` renders **1.65px at 1024px** and 0.97px at 768px — indistinguishable from the 1px `bg-foreground/25` axis beside it, so "+1%" and "no change" look identical. Use a px floor (`minWidth: "3px"`) for any minimum-visibility segment inside a flexible track.
- **`items-baseline` on a values row containing an `inline-flex items-center` child is fine here** — measured, the three numbers (11.5/13/12.5px) do share one baseline; the boxes differ in height but that is expected and invisible. Not a defect.
- A `hidden sm:flex` header over `flex-wrap` rows means the axis key disappears exactly where the bar wraps to its own line; below the header's breakpoint the diverging bar's centre-is-zero / left-is-down encoding is carried by nothing but a 1px `foreground/25` line. The footnote must state it, or the encoding is undecodable on mobile.

**Round-5 additions — all re-measured in the harness, header now `lg:` (mirroring exact, `catΔ/barΔ/barWΔ/v1RΔ/ax0Δ` all 0.00 at 1024/1100/1280/1440; header is one 14.25px line; `document.scrollWidth == clientWidth` at 360–1440 for typical data).**

- **`min-w-0` does NOT cap a flex item's min-content *contribution*; `width:0` does, and `flex-basis:0%` does NOT.** Measured on the movers row's name span (`min-w-0 flex-1 truncate`): with long category names the card is pinned to a **361.53px min-content floor**, so the page scrolls 58px @320 / **18px @360 / 3px @375**. `style.width=0` → floor drops to 314px and overflow goes to 0 at 360/375. `flex-basis:0%` changes nothing, because a percentage basis is treated as `content` during intrinsic sizing. Corollary: `w-0` is SAFE alongside `lg:flex-none lg:basis-48` — basis is emitted after `flex` in v4, so the used size at lg is still 192px (verified: nameW 192 at 1024/1280/1440 with `width:0` applied).
- **The value columns' fixed widths also set a floor:** `6.75+4.75+3.5rem` + 2×`gap-x-3` = **264px** of `shrink-0`, so the movers card can never be narrower than 314px however short the names. That's why 320px still overflows 10px after the name fix. Those widths exist only to align with the `lg:` header, so they can be `lg:`-prefixed.
- **`moverAmount` compacts at ≥100,000** (`formatCompact`: `.1f K` then `.1f M`), so real strings are short and the round-4 6.75/4.75/3.5rem trim holds. Measured worst cases in Geist tabular-nums: `1000.0K → 1000.0K` and `0 → 1000.0M` fit 108px; `+1000.0M` with the `size-3` arrow = **78.91px vs the 76px box (0.02px over)** — at the limit, and `formatCompact` has no cap past `M`. Don't re-widen these for hypothetical 8-digit raw amounts; `35,294,543 → 41,200,000` never renders.
- **The zero-axis span is painted UNDER the bar fill.** Both are `absolute` at `z-auto` and the axis is DOM child 0, the fill child 1 → the fill wins. `elementFromPoint` at the track centre returns the FILL on 4 of 6 rows (every rise, since `left:50%` starts exactly on the axis). So the "centre line is no change" the footnote promises is invisible on the common case, at every width — worst in the 640–1023 band where the bar is a full-card-width 554–678px strip with no header. Fix is a DOM reorder (axis after fill) or `z-10` on the axis.
- **`VelocityBars` (replaced `VelocityRow`) is 131.5px tall** — the "~130px" target is exact. But the `lg:grid-cols-[minmax(0,1.4fr)_minmax(0,1fr)]` row is `align-items: stretch`, so the card is stretched to the YoY card's 391.5px and leaves **151px of dead space** at ≥1024. Compacting a card in a stretched grid row does not shrink the row; it converts content into void.
- **Velocity label column `minmax(0,4.5rem)` = 72px.** Measured @11px Geist: `This quarter` 59.16, `Last quarter` 60.86, `Jun 30–Jul 6` 66.84, `Dec 29–Jan 4` 70.09, `August 2025` 65.58 all fit; **`September 2025` = 85.48 → truncates to "September 2…"**. So in history mode the *viewed* period's name can be cut while the prior period's below it is intact.
- **The dashed `border-[1.5px] border-dashed` outline bar reads cleanly at `h-2`** inside `overflow-hidden rounded-full` — screenshotted at 4× at 375/1024/1440, it is a legible dashed pill, not a blob. Not a defect.
- **`var(--muted)` is a real custom property** (`index.css` `:root` = `hsl(180 8% 13%)` → rgb(30,36,36)), so the null-delta chip does get a background. But the chip is **45.5px tall with a delta and 36.5px without** — a 9px height flip between "has a prior period" and "doesn't", i.e. a step-induced shift below `lg`.
- Chip contrast measured on the composited tint (rgb(47,35,34) for expense at 12%): 17px semibold `--expense` value = **5.31:1**, 11px `muted-foreground` sub = **6.45:1** (6.73:1 on the `--muted` variant). Both pass AA; the chip tint itself is only 1.17:1 vs `--card` but visibly reads as a panel.
